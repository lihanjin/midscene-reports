PR-Agent 代码审查

Secret Exposure

This adds a live-looking Figma access token to a tracked environment file. Anyone with repository access can use it to access the associated Figma resources; revoke it and move it to a CI secret or other untracked secret store.

CAPTCHA Bypass

The company-ID exemption disables CAPTCHA for every user in tenants 473 and 4730, and the session-storage marker is also directly writable by any client. Since CAPTCHA is an abuse-control measure, these client-side checks allow anyone to bypass it for verification-code sends; keep exemptions server-controlled and restrict any E2E bypass to a non-production test environment.

Lost Currency

`buildBankReceiverFormValues` restores the new bank country and bank details but omits `bankCurrency`. When editing an existing receiver, the saved currency is therefore blank, so the user may submit an incomplete or unintended currency value.

XSS Risk

`displayHtml` is inserted without HTML sanitization. If an agreement resource contains attacker-controlled markup or attributes (for example, an event handler), opening the preview can execute script in the application origin. Sanitize the HTML before rendering it.

Missing Result Details

The success view now passes an empty summary and only the proposal number, removing the transferred amount, recipient, and creation time from the success result. Users therefore cannot verify the key details of the completed remittance from this screen.

Dead Action

The success screen replaces the result actions with a single “view records” button and no longer exposes the previous back-home action. Users who want to leave the result screen without navigating to records have lost that available action.

Existing Files

This replaces the receiver's existing `otherFiles` with the newly uploaded remittance attachments. If the receiver already has KYC files in that field, they are omitted from the submitted order; preserve them when adding the new attachments.

Missing Refresh

`refreshRepaymentTable` is emitted only by `handleClose`. If the customer closes the modal while the VA-account request is still loading, or the request fails and shows the error state, the repayment table is refreshed despite no repayment being made. Move this event to the successful repayment/confirmation path if it is intended to indicate an updated repayment record.

Stale Tab

`activeTab` is initialized from `router.query.tab` only on the first render. If this section mounts before the query is populated (as can happen with Next.js router hydration), it stays on the transaction tab even when the URL later resolves to `?tab=remittance`. Synchronize the state when the query becomes available.

Incorrect Status

This renders every loan transaction as completed, regardless of its actual status. Transactions that are pending or failed will therefore be mislabeled in both the table and the mobile cards; preserve the per-row status mapping.
